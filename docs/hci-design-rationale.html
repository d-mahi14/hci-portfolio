HCI & UX Design Rationale

Author: Mahi Desai • Platform: Semantic HTML5, CSS3, Vanilla JS • Standards: Targets WCAG 2.1 Level AA (individual colour pairs meeting 7:1 noted per pair); Nielsen's 10 Heuristics, Shneiderman's 8 Golden Rules, Fitts's & Hick's Laws.

1. Color Contrast & Accessibility (WCAG 2.1 Level AA)

The site targets WCAG 2.1 Level AA. Individual colour pairs that also exceed the AAA contrast threshold (7:1 normal text) are noted per pair below. Ratios are computed with the complete WCAG relative luminance formula including the sRGB linearisation step:

Relative Luminance: L = 0.2126 × Rlin + 0.7152 × Glin + 0.0722 × Blin
Contrast Ratio: (L1 + 0.05) / (L2 + 0.05)   [where L1 > L2]

2. Mapping to Nielsen's 10 Usability Heuristics

1. Visibility of System Status

  • Reading Progress Bar: Fixed 3px gradient line at top of viewport indicates scroll depth.
  • ScrollSpy Navigation: Header dynamically highlights current section with aria-current="page".
  • Theme Toggle: Button displays alternate state icon (Sun ☀️ / Moon 🌙) with accessible text.

2. Match Between System & the Real World

  • Information architecture mirrors authentic engineering milestones: Foundations (Academic), Delivery (Projects), and Reach (Contact).
  • Standard domain concepts (eDNA, VAE, Groq LLM, Supabase RLS) used accurately without invented claims.

3. User Control & Freedom

  • Dismissible Modals: Project detail dialogs dismiss via Escape key, ✕ button, or backdrop click.
  • Focus Restoration: Closing a dialog returns focus to the exact card button that opened it.
  • Back-to-Top Button: Floating anchor appears after scrolling 400px down for instant return to top.

4. Consistency & Standards

  • Tokenized 8pt Grid: Standard CSS custom properties (--space-1 through --space-16) regulate all gutters.
  • Standard Element Semantics: Buttons trigger actions; anchors navigate; external links open safely with rel="noopener noreferrer".

5. Error Prevention

  • Live Field Validation: Form fields validate on blur and input, highlighting issues before submission.
  • Descriptive Required Indicators: Required fields feature an asterisk and clear labels.

6. Recognition Over Recall

  • Category Filter Chips: Projects categorized into All, AI/ML, Deep Learning, Full-Stack for immediate visual recognition.
  • Technology Pills: Distinct badges highlight frameworks (PyTorch, TensorFlow, React.js) on every card.
  • Resume Size Indicator: Explicit 154 KB file size badge informs users before downloading.

7. Flexibility & Efficiency of Use

  • Instant Blog Search: Real-time substring filter searches articles across titles, tags, and content.
  • Dual SUS Modes: Supports both All-Positive Mode (5 = Best) and Standard Brooke SUS (Alternating polarity).
  • Keyboard Navigation: Fully operable via keyboard with high-contrast :focus-visible outlines.

8. Aesthetic & Minimalist Design

  • Deep navy canvas paired with teal accents; visual hierarchy prioritizes core engineering artifacts.
  • Clean borders delimit sections using Gestalt Common Region principles without visual clutter.

9. Help Users Recognize, Diagnose, & Recover from Errors

  • Field validation shows specific messages: "Please enter a valid email address" rather than generic warnings.
  • SUS calculator shows an interactive question-by-question breakdown explaining how points are calculated.

10. Help & Documentation (In-Interface Contextual Help)

In-interface contextual help is integrated directly across the user journey (Nielsen #10, Shneiderman #8):

  • Project Filter Helper Text: Explicit guide directly below filter chips ("Choose a category to narrow the projects. Select 'All' to reset.").
  • Blog Search Hint: Subtitle informing visitors that search operates in real-time across titles, tags, and body content.
  • Form Field Hints (WCAG 3.3.2): Contextual hints beneath each contact input (e.g. "We'll only use this to reply to you") programmatically linked via aria-describedby.
  • SUS Scoring Documentation: Collapsible "How SUS scoring and benchmarks work" explanation and 1–5 scale legend inside the evaluation card.
  • Accessible Tooltips (WCAG 1.4.13): Controls such as the theme switcher, Rate Site button, and Export buttons feature keyboard-focusable, hover-persistent, and Esc-dismissible tooltips.
  • Project Documentation: Dedicated HCI design rationale and usability evaluation files exist in the footer as external project documentation, distinct from the in-app help system.

3. Shneiderman's 8 Golden Rules Integration

  1. Strive for Consistency: Standardized typography scale, button heights (min 44px), and card radii.
  2. Cater to Universal Usability: Strict WCAG 2.1 Level AA compliance (with key pairs exceeding AAA 7:1) and complete prefers-reduced-motion support.
  3. Offer Informative Feedback: Visual hover states, active navigation indicators, and real-time form validation.
  4. Design Dialogs to Yield Closure: Honest, real closure mechanisms:
    • Contact Form: While dispatching, the submit button is disabled with status "Sending..." and aria-busy="true". On confirmed HTTP 2xx from Formspree, an inline success alert (role="status") confirms delivery and resets the form. On error, a specific error alert (role="alert") retains typed text and provides an email fallback. When placeholder mode is detected, the UI explicitly announces that it opened the email application, never falsely claiming delivery.
    • SUS Evaluation Form: Submitting displays an immediate calculated score badge, calibrated Sauro & Lewis (2016) grade, and an expandable question-by-question point breakdown.
  5. Prevent Errors: Pre-submission input checks prevent blank or malformed inquiries.
  6. Permit Easy Reversal of Actions: Modals close with Escape key; SUS responses can be reset with one click.
  7. Support Internal Locus of Control: Users control theme, project filter categories, and article search.
  8. Reduce Short-Term Memory Load: Tech stack chips on cards prevent needing to remember project details.

4. Fitts's Law & Hick's Law Engineering

Fitts's Law (Touch Target Sizing & Corners)

Every interactive element (buttons, filter chips, theme toggles, modal close buttons, social icons) has a minimum touch target of 44px × 44px, satisfying WCAG 2.5.5. The sticky header occupies the screen top, and the back-to-top button is anchored in the bottom-right corner for effortless acquisition.

Hick's Law (Cognitive Load Reduction)

The top navigation is consolidated into 6 primary destinations plus a direct "Rate Site ★" link. Project cards use 4 clean filter chips instead of complex nested menus.

5. Gestalt Principles in Layout Design

  • Proximity: Degree titles, institution names, and dates are grouped closely within individual timeline cards.
  • Common Region: Cards have distinct borders and surface backgrounds that clearly enclose related content.
  • Similarity: All skill chips and filter pills share uniform border radius, padding, and font styling.
  • Continuity: The vertical timeline line guides the eye smoothly through chronological milestones.
